# 소주제 층 — Part 안을 `####` + 표 여러 개로 쪼개기

## 문제

`Part 6 — 20:26–24:58 | 쿠팡 AI 팩토리 추진 · 일본 나무라조선소 LNG 운반선 도크 신설 · 모더나 mRNA 항암백신 임상 3상` 하나에 표 하나, 그 안에 행 10~13개가 평평하게 쌓인다. 서로 무관한 세 기사가 한 표에서 섞이고, 목차는 Part 까지만 내려간다.

> **HMW** — Part 안을 소주제 단위로 접근·복습할 수 있게 쪼개면서, 노트를 '기록' 이상으로 만들지 않을 수 있을까?

## 근거 — 정보는 이미 있었고 상한이 버렸다

`SKILL.md` 0.5절 유형 표에 이렇게 적혀 있었다:

> 뉴스 브리핑형 | 최대 8개 | 기사·토픽 전환에서 자른다. **상한을 넘으면 인접 토픽을 묶고 제목에 `·` 로 나열**

제목의 `·` 는 스타일이 아니라 **구간 상한 8개를 넘겨 토픽을 눌러 담은 흔적**이다. `outliner` 는 "쿠팡 AI 팩토리"와 "모더나 임상 3상"이 별개 토픽인 걸 이미 알고 있었고, 상한 때문에 합치면서 `·` 로 이어 붙였다. 그러니 이 작업은 새 정보를 만드는 게 아니라 **outliner 가 알았다가 버린 층을 되살리는 일**이다. 새 에이전트도 자막 재분석도 필요 없다.

## 채택한 방향

```markdown
## Part 6 — 20:26–24:58 | 쿠팡 AI 팩토리 추진 · 일본 나무라조선소 … · 모더나 …   ← h2 유지

#### 쿠팡 AI 팩토리 추진                                                        ← 소주제 = h4

| 단서/키워드 (Cues & Questions) | 핵심 필기 내용 (Detailed Notes) |
| --- | --- |
| `[20:26]` … | - … |

#### 일본 나무라조선소 LNG 운반선 도크 신설

| … |
```

- **Part 은 `##` 유지.** `@media print { h2 { break-before:page } }` 가 Part=페이지 분할을 담당한다. h3로 내리면 문서에 h2가 없어져 이 규칙이 통째로 죽는다.
- **소주제는 `####`.** `toc_depth: "2-3"` 이라 목차에는 안 들어가고, `python-markdown` 의 toc 확장은 depth 밖 헤딩에도 id 를 붙이므로 **앵커는 공짜로 생긴다.** 겉모습은 CSS 한 줄로 굵은 문단과 같게 맞췄다.
- **소주제는 `outliner` 구간 제목의 ` · ` 나열**이고 `section-note` 가 그것을 쪼갠다. 새 채널도 새 형식도 없다.

## 구분자는 ` · ` (앞뒤 공백) 뿐 — 실측

제목의 가운뎃점을 그냥 쪼개면 안 된다. `·` 는 소주제 구분자이면서 한국어 낱말 나열 부호이기도 하다:

```
Part 4  | 어제 코스피·코스닥 마감 상황과 업종별 등락             ← 소주제 1개
Part 13 | 국내 증시 — 코스피·코스닥·환율·수급·삼성전자 소액주주·  ← `·` 9개지만 소주제 1개
          SK하이닉스·농심 등 음식료주·실리콘투·공모주 일정
```

**구분은 공백이 한다.** `notes/` 의 Part 제목 16개를 전부 돌린 결과:

| 규칙 | 결과 |
|---|---|
| ` · ` (앞뒤 공백) 로만 분할 | **16 / 16 정확** |
| 이름 안쪽에 붙은 `·` 가 있는 제목 | 9개 — 전부 안 쪼개짐 |

붙은 `·` 는 흔하지만(9/16) 전부 낱말 잇기였고, 떨어진 ` · ` 는 전부 진짜 소주제 경계였다. 예외가 없다.

다만 이 규약이 지금까지 **프롬프트에 적혀 있지 않았다.** `SKILL.md` 는 "제목에 `·` 로 나열" 이라고만 했고 공백은 우연히 일관됐다. 그래서 outliner 프롬프트에 규약을 명문화했다 — 이 한 문장이 별도 소주제 출력 형식을 통째로 대신한다.

## 데이터 흐름 (새 산출물 없음)

```
outliner 구간 제목:  쿠팡 AI 팩토리 추진 · 일본 나무라조선소 … · 모더나 …
                                        │
 section-note 가 ` · ` 로 분할  ────────┘
                                        ▼
                      #### 쿠팡 AI 팩토리 추진   + 표
                      #### 일본 나무라조선소 …   + 표
                      #### 모더나 …             + 표
```

outliner 출력 형식은 **바뀌지 않는다.** `--segments` 도, 에이전트 간에 오가는 값도 그대로다. `section-note` 는 이미 구간 제목을 받고 있으므로 넘길 것도 늘지 않는다. 제목에 ` · ` 가 없는 Part 은 소주제 하나 · 표 하나로 현행과 같아진다.

## 검증한 것

`md2html.py` 에 실제로 통과시킨 결과다. 추정이 아니다.

| 확인 | 결과 |
|---|---|
| 소주제 `**bold**` | `<p><strong>…</strong></p>` — id 없음, 목차 없음 |
| 소주제 `#### h4` | `<h4 id="쿠팡-ai-팩토리-추진">` — **id 붙고 목차엔 안 들어감** |
| Part 을 `###` 로 강등 | 목차·앵커는 정상, **인쇄 페이지 분할이 죽음** |
| Part 제목 16개 ` · ` 분할 | 16/16 정확. 붙은 `·` 9개 전부 안 쪼개짐 |
| Part 4 (`코스피·코스닥`) | 소주제 1개 → 표 1개. 오분할 없음 |
| `--selftest` | ok (h4 앵커 유무 assert 2개 추가) |

## 안 하는 것 (과 이유)

- **소주제별 요약 줄** — 코넬 준수도는 오르지만, 사실 나열을 한 줄로 줄이는 건 무엇을 버릴지 고르는 일이라 "판단 금지"와 정면 충돌한다. 노트는 정리까지만 한다.
- **`<details>` 로 노트 열 접기** — 큐만 보고 인출하는 코넬 본래 동작이지만, '정리'를 넘어 '복습 도구'로 가는 변경이다. 필요해지면 그때.
- **큐 열 압축** — 큐:노트가 1:1이라 Reduce 가 없다는 지적은 유효하나, 이번 변경 범위 밖이다. 소주제 제목과 글자 그대로 같은 굵은 소제목만 첫 행에서 빼도록 한 줄 넣었다.
- **기존 `notes/*.md` 2개 재생성** — 자막 재추출 + 에이전트 전체 재실행 비용이 든다. 다음 영상부터 새 형식.
- **Part 을 h3로 강등** — 인쇄 페이지 분할을 잃는다. 얻는 게 없다.
